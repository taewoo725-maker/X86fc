X86FC 0.12.8 - MSX-DOS2 / Nextor 파일 관리자 (x86 File Commander)
만든이: KimTaeWoo   라이선스: GPL-3.0-or-later

[실행] MSX2 이상 + MSX-DOS 2 에서 X86FC 를 치면 두 패널이 뜹니다.
       X86FC.INI 는 X86FC.COM 과 같은 폴더에 둡니다 (없어도 동작).

[키]
 F1 도움말 · F2 텍스트 보기 · F3 보기+편집 · F4 Screen(화면 방식 전환) · F5 MSX-BASIC (CALL SYSTEM 하면 돌아옴)
 F6 이름 바꾸기 · F7 폴더 만들기 · F8 정렬(이름·확장자·날짜) · F4 화면 방식 전환(글자 → SCREEN 7 → SCREEN 7 한글(7H) → 글자) · F9 드라이브 · F10 끝
 (F6~F10 = Shift+F1~F5. 맨 아래 안내 줄은 평소 F1~F5, Shift 를 누르고 있으면 F6~F10 이 보입니다)
 Quick-Dir(^B) 는 가운데 팝업 상자: ↑↓ 로 고르고 RETURN 으로 이동 (0-9/A-J 로 바로 이동도 됨), INS 현재 폴더 추가, DEL 지우기, ESC 닫기
 사용자 메뉴(Ctrl+G) 도 같음: ↑↓ + RETURN 으로 실행 (0-9/A-J 직접 선택, INS 추가, F2 고치기, DEL 지우기)
 F9 = 활성 패널의 드라이브 바꾸기 (설치된 드라이브만 풀다운으로: ↑↓ Enter, 글자 = 바로 선택, ESC 취소)
 Ctrl+F3 이 확장자의 프로그램 목록 관리
 Ctrl+A 모두 선택 · Ctrl+F 파일 찾기 · Ctrl+W 트리 · Ctrl+Enter 이름을 명령줄에
 Home 루트 · Backspace 위 폴더 · INS 복사 · DEL 삭제 · SELECT 이동 · Space 선택 · Tab 패널 전환
 Enter 폴더 들어가기 / 프로그램 실행 / 연결된 프로그램 열기 · / 명령줄 · ^B Quick-Dir · ESC DOS 화면 보기 (끝내기는 F10)
 글자를 치면 그 글자로 시작하는 항목으로 이동.

[SCREEN 7 모드 (0.9.5 새 기능)]
 F4 로 글자 화면 ↔ SCREEN 7 전환 (고른 방식은 INI 의 SCREEN = 0 / 7 줄에 자동 저장되어, 다음 시작도 그 방식으로 뜹니다). SCREEN 7 은 파일 형식별 아이콘·색, 팝업 색이 나옵니다.
 시작 옵션: X86FC /7 = SCREEN 7 로 시작, X86FC /0 = 글자 화면으로 시작. 고른 방식은 INI 의 SCREEN 줄에
 저장되어 다음부터 옵션 없이 X86FC 만 쳐도 계속 그 방식으로 시작합니다. (INI 의 SCREEN = 7 / 0 을 직접 고쳐도 됨)
 "COLOR 확장자 = 번호" 로 확장자별 글자 색 지정 (번호 0~15, 서로 다른 색 7가지까지). 예: COLOR TXT = 10
 ※ 실기 속도는 아직 확인 못 했습니다. 느리면 F4 로 글자 화면으로 돌리세요.

[SCREEN 7 한글 모드 7H (0.12.0 새 기능)]
 F4 를 누를 때마다 글자(SCREEN 0) → SCREEN 7 → SCREEN 7 한글(7H) → 글자 순서로 바뀝니다. 7H 는 한글 파일 이름을 9x9 점글꼴로 보여 줍니다.
★ 7H 의 한글 글꼴은 X86FC.OVL 뒤쪽에 들어 있습니다 (0.12.14 부터. 옛 X86FC.HGL 은 쓰지 않음). 글꼴이 없는 옛 OVL 이면 F4 가 7H 를 건너뜁니다.
 - 줄 높이 10점(21줄), 목록 15줄. 한글 한 글자 = 글자 칸 2개(12점)라 이름 칸(16칸 = 한글 8자)·크기·날짜 열 위치는 그대로입니다.
 - 글꼴은 Galmuri9 (SIL OFL 1.1, Lee Minseo) 의 한글 완성형 11172자. X86FC.HGL 은 소스 zip 의 mkhgl.py 로 만듭니다 (python3 mkhgl.py Galmuri9.bdf X86FC.HGL). Galmuri 라이선스(OFL) 전문은 Galmuri_OFL_LICENSE.txt.
 - 글꼴은 글자를 처음 볼 때 파일에서 읽어 VRAM 에 기억(캐시)해 두므로, 처음 한글 이름이 많은 폴더를 열면 잠깐 느릴 수 있습니다.
 - 팝업·드라이브 풀다운·정렬 메뉴·도움말·편집기·찾기·트리·사용자 메뉴는 SCREEN 7 처럼 8점 줄로 그려지고, 닫으면 7H 화면으로 되돌아옵니다.
 - INI 의 SCREEN = 7H (시작 때 HGL 이 없으면 SCREEN 7), 시작 옵션 X86FC /7H. SCREEN 0 · 7 에서는 한글이 지금처럼 ? 로 보입니다.
 - 한글 이름 파일의 이름 바꾸기는 7H 에서 막아 둡니다 (입력은 ASCII 만 되므로 SCREEN 0 · 7 에서 하세요). 복사·이동·삭제는 한글 이름을 그대로 보존합니다.
 ※ 실기 속도(한글 글꼴 읽기·그리기)는 아직 확인 못 했습니다.

[연결이 없는 파일] 연결된 프로그램이 없는 확장자를 Enter 로 열려고 하면 "No program is linked to .XXX - link one now?" 팝업이 물어봅니다. 예(Y/Enter) 를 고르면 Ctrl+F3 과 같은 "Open with" 팝업으로 가서 INS 로 프로그램을 고르면 등록되고 바로 실행됩니다. 아니오(N) 는 그냥 닫힙니다.

[긴 이름] 파일 목록은 8.3 이름이고, 아래 정보 줄에 커서 파일의 긴 이름이 나옵니다 (한글은 SCREEN 7 한글 모드 7H). 정렬은 짧은 이름(8.3) 기준.

[INI 의 SORT · BGP]
 SORT = name / ext / size / date   시작할 때의 정렬 (F8 로 고르면 이 줄이 자동으로 저장되어 다음에도 유지).
 BGP = 215                       SCREEN 7 바탕색 (R G B 각 0~7, 예 215 = 짙은 파랑 계열, 300 = 어두운 빨강).
 아이콘·색이 나오는 파일 형식이 늘었습니다 (그림·소리·글·압축·롬 약 90가지, M 이 쓰는 확장자 포함).

[ESC 와 화면 기억] 입력한 글이 없을 때 ESC = 처음 DOS 화면 보기, 다시 ESC 로 돌아옵니다.
 X86FC 를 끝내면(F10) 시작하기 전의 DOS 화면과 커서 자리를 그대로 되돌립니다.

[사용자 메뉴 Ctrl+G] 자주 쓰는 명령을 INI 에 등록해 두고 팝업에서 0-9/A-J 로 골라 실행합니다 (최대 20개).
 팝업 안에서 직접 고칠 수 있습니다 (INI 의 MENU 줄이 바뀝니다):
   INS = 추가: 프로그램 고르기 창에서 프로그램을 고르면 제목 = 파일 이름, 명령 = "경로 %s" (확인 창에서 인자를 고침).
         고르기 창 맨 위 "<type it...>" 를 고르면 제목·명령을 직접 입력.
   F2 = 고치기: 제목을 고친 뒤 프로그램을 새로 고르거나(또는 "<type it...>" 로 옛 명령을 직접 고침).
   DEL = 지우기.
 MENU 제목 = 명령      예) MENU Games = CD B:\GAMES   (CD = 그 폴더로 이동)
                           MENU Trash = DEL A:\TRASH\*.*
                           MENU Edit  = APED %s        (%s = 커서 항목 이름, %f = 확장자 뺀 이름)
 CD 가 아닌 명령은 아래 줄 명령줄('/')과 같은 방식으로 실행되고, 끝나면 "Press any key" 뒤 X86FC 로 돌아옵니다.

[명령줄 기록 (0.12.8 새 기능)]
 '/' 명령줄(Ctrl+Enter 포함)에서 ↑ 를 누르면 지난 명령이 한 칸씩 올라오고(최대 4개), ↓ 로 내려갑니다(맨 아래 = 빈 입력). 불러온 글에 이어서 고쳐 쓸 수 있습니다.
기록은 X86FC.INI 의 HIST 줄(4개)에 저장돼 프로그램을 다녀온 뒤에도 남습니다. 맨 앞과 같은 명령은 다시 넣지 않습니다.
[7H 글꼴 캐시 (0.12.8)]
한글 글꼴 캐시를 2갈래로 바꿔, 글자 두 개가 같은 칸을 두고 서로 밀어내며 매번 글꼴(OVL 안)을 다시 읽던 일을 줄였습니다 (한글이 다양한 폴더).

[F2 보기 찾기 (0.12.52 새 기능)]
 F2 텍스트 보기에서 Ctrl+F = 찾을 글 입력(영문, 대소문자 무시), n 또는 F3 = 다음, p = 이전. 찾은 줄이 화면 맨 위로 옵니다. 없으면 "Text not found". UTF-8 한글은 찾지 못합니다(영문만).

[찾기·트리의 긴 이름 (0.12.51 새 기능)]
 Ctrl+F 찾기 결과와 Ctrl+W 트리에서 ↑↓ 로 고른 항목의 긴 이름이 맨 아래 줄에 "Long name: ..." 로 나옵니다 (긴 이름이 없으면 안내 글/빈 줄). 7H(SCREEN 7 한글)에서는 한글 이름도 한글로 보이고, 그 밖의 화면 방식에서는 ?? 로 보입니다.

[풀다운 깜빡임 개선 (0.12.7)]
 ↑↓ 로 줄을 고르는 모든 창(열기 목록 풀다운 = Ctrl+F3 / 연결 프로그램이 여럿일 때 Enter, 프로그램 고르기 파일 선택 창, F8 정렬 풀다운, Ctrl+F 찾기 결과, Ctrl+W 트리)이
 F9 드라이브 풀다운처럼 창·화면 전체를 다시 그리지 않고 바뀐 두 줄(예전 선택 줄·새 선택 줄)만 다시 그립니다. 목록이 넘어갈 때만 목록 줄들을 다시 그립니다.
 열기 목록을 ESC 로 닫은 뒤 팝업 자국이 남던 것, 파일 선택 창 맨 아래 테두리에 항목 글이 겹쳐 쓰이던 것도 고쳤습니다.

[프로그램 실행 방식 (0.12.6 에서 바뀜)]
 Enter(COM·BAT·연결 프로그램)·사용자 메뉴·아래 줄 명령줄·F5 가 프로그램을 돌릴 때, 예전처럼 메모리 윗쪽(D000h)에 되돌아올 코드를 남겨 두지 않습니다.
 대신 현재 상태(두 패널의 폴더·커서·선택, 활성 패널)를 환경 변수 X86FC 에 저장하고, 현재 드라이브·폴더를 활성 패널로 맞춘 뒤,
 X86FC.COM 이 있는 폴더에 짧은 배치 파일(X86FCR1.BAT / X86FCR2.BAT, 번갈아 씀)을 쓰고 키 버퍼에 그 이름을 넣어 X86FC 를 완전히 끝냅니다.
 COMMAND2 가 배치를 실행해 프로그램을 돌리고, 배치 마지막 줄이 X86FC 를 다시 띄워 저장해 둔 상태로 복귀합니다 (M 과 같은 방식).
그래서 프로그램이 메모리를 얼마나 쓰든(TPA 전체를 덮어써도) 되돌아옵니다. 화면 방식(0/7/7H)·정렬은 X86FC.INI 에서 다시 읽어 유지됩니다.
 - 배치 파일 이름은 키 버퍼(40칸)에 들어가야 해서, X86FC.COM 폴더 경로가 길면(25글자 넘음) 그 드라이브 루트에 씁니다.
 - 지난번 배치 파일은 X86FC 가 돌아와 시작할 때 지웁니다. X86FC 를 F10 으로 끝낸 뒤에는 작은 X86FCR?.BAT 한 개가 남을 수 있습니다(지워도 됩니다).
 - 프로그램을 Ctrl+C 로 끊으면 배치도 끊겨 X86FC 로 자동 복귀하지 않을 수 있습니다(DOS 프롬프트에서 X86FC 를 다시 치세요).

[X86FC.INI] 확장자 = 명령 (%s = 고른 파일 경로, %f = 확장자를 뺀 경로). 명령이 여럿이면 Enter 때 풀다운으로 고름(맨 위가 기본).
 여러 명령은 한 줄에 ';' 로 쓰거나(최대 8개) 같은 확장자 줄을 여러 줄 씁니다.
 예) TXT = AKID %s;HV %s;NV %s        LZH = LHEXT E %s;LHEXT L %s

[Quick-Dir · 사용자 메뉴 ↑↓ 선택 (0.12.10)]
 고른 항목은 줄 앞에 > 가 붙고, ↑↓ 를 누르면 예전·새 선택 줄 두 줄만 다시 그려 깜빡이지 않습니다 (SCREEN 0·7·7H 모두).

[한글 입력 (0.12.11 새 기능, 7H 에서만)]
F6 이름 바꾸기·F7 폴더 만들기 입력 창에서 MSX 본래의 한/영 키(일본 MSX 의 KANA/CODE 키, 키보드 행렬 6행 비트 4)로 한/영 전환 (안내 줄 끝에 HAN / ENG 표시, KANA 램프도 켜지고 꺼짐). 한글 모드에서는 영문 자판을 두벌식으로 읽습니다:
   ㅂq ㅈw ㄷe ㄱr ㅅt ㅛy ㅕu ㅑi ㅐo ㅔp / ㅁa ㄴs ㅇd ㄹf ㅎg ㅗh ㅓj ㅏk ㅣl / ㅋz ㅌx ㅊc ㅍv ㅠb ㅜn ㅡm, Shift+q w e r t = ㅃ ㅉ ㄸ ㄲ ㅆ, Shift+o p = ㅒ ㅖ
 - 겹모음(ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ)·겹받침(ㄳ ㄵ ㄶ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅄ)이 되고, 받침 뒤에 모음이 오면 받침이 다음 글자로 넘어갑니다. BS 는 조합 중인 글자를 종성 -> 중성 -> 초성 순으로 한 단계씩 지웁니다.
 - 자음만 있는 글자(모음 전)는 그 자음 + ㅡ 모양으로 보이고, 모음을 치면 완성됩니다 (자음 뒤 모음 없이 끝내면 그 모양 그대로 이름에 들어갑니다). 맨 앞의 모음은 ㅇ + 모음 글자가 됩니다. 옛 이름(7H 에서 보이는 한글 긴 이름)도 바꿀 수 있습니다.
 - 한글 이름은 VFAT 긴 이름(UCS-2)으로 기록되고, 8.3 별칭(FILE~1 처럼 영문·숫자만)이 자동으로 만들어집니다 (fsck.vfat·mdir 로 확인).
 - 입력 창의 한글은 팝업 안에서 8점 줄에 맞춰 9x9 글꼴의 아래 두 줄을 겹친 8줄로 그려 약간 촘촘합니다. 명령줄(/)에는 한글이 없습니다.
 - 메모리 때문에 이동(SELECT)을 본체에서 오버레이(OVL 5번 칸)로 옮겼습니다 (OVL 19968바이트, 이동할 때 한 번 읽음).

[팝업 글의 한글 (0.12.12)]
 7H 에서 삭제 확인("Delete 한글 이름?")·덮어쓰기 확인·읽기 전용 삭제 확인 같은 팝업에 들어가는 파일 이름(긴 이름)이 ? 대신 한글로 보입니다 (이름이 길면 20바이트까지, 한글 한 글자를 쪼개지 않음). 한글 글자는 8점 줄 팝업에 맞춰 아래 두 줄을 겹친 8줄 글꼴이라 약간 촘촘합니다. SCREEN 0·7 은 예전처럼 ? 로 보입니다.

[정보 줄 화살표 · F4 이름 (0.12.13)]
 아래 정보 줄의 활성 패널 표시 화살표가 줄 맨 앞이 아니라 활성 패널 쪽 끝으로 갑니다: 왼쪽 패널 = 줄 맨 왼쪽 <- , 오른쪽 패널 = 줄 맨 오른쪽 -> (SCREEN 7·7H 는 8x8 화살표 아이콘). 긴 이름·N items 글자는 그대로 (이름 56칸, N items 는 60칸부터).
 맨 아래 기능키 줄의 4Graph 를 4Screen 으로 바꿨습니다 (F4 = 화면 방식 전환). F1 도움말은 이미 Screen 으로 적혀 있습니다.

[파일 3개로 (0.12.14)]
 영구 파일을 X86FC.COM + X86FC.OVL(글꼴 포함) + X86FC.INI 세 개로 줄였습니다. SET(화면·정렬)·MNU(메뉴)·HIS(명령줄 기록)·QD(Quick-Dir)는 INI 줄(SCREEN·SORT·MENU·QDIR·HIST)로, HGL(글꼴)은 OVL 뒤로 합쳤습니다.
 INI 는 이제 전체를 줄 단위로 읽고 쓰므로 크기 한도가 없습니다 (연결 줄이 몇 KB 뒤에 있어도 됨). 저장은 그 키의 줄만 지우고 끝에 새로 적으며(임시 파일 X86FC.TMP -> INI 교체, 실패하면 옛 INI 유지) 다른 줄·주석·순서는 그대로입니다.
 이행: 옛 SET·MNU·QD·HIS 가 있으면 처음 실행 때 INI 로 옮기고 지웁니다 (옛 HGL 은 지우지 않으니 확인 후 직접 지우세요).
 한/영 키: 7H 이름 입력의 한/영 전환은 TAB 이 아니라 MSX 한/영(KANA/CODE) 키입니다 (입력 창을 닫으면 KANA 잠금은 꺼짐).

[메모리 정리 (0.12.15)]
 F9 드라이브 풀다운·F8 정렬 풀다운 코드를 본체에서 오버레이 5번 칸(이동과 같은 칸)으로 옮겨 본체 메모리 여유를 약 1KB 로 늘렸습니다 (다음 기능용). 화면·동작은 그대로입니다.

[SCREEN 7 26줄 · 7H 9점 줄 (0.12.16)]
 SCREEN 7 은 위 여백을 2점으로 줄여 26줄(208점)로 뜹니다: 목록 20줄, 정보 줄·기능키 줄이 아래로 내려갑니다. 팝업·도움말·보기·편집기·찾기·트리는 그대로 24줄 기준(위쪽에 그려짐)입니다. SCREEN 0 은 24줄 그대로입니다.
 7H 는 기본 21줄(줄 높이 10점)이고, X86FC.INI 에 LINES = tight 를 적으면 줄 높이 9점 23줄(목록 17줄, 한글 9x9 글꼴의 위아래 간격 0점)로 뜹니다. 한글이 빽빽하지만 읽을 수 있고 줄이 2개 더 들어갑니다 (INI 에 적지 않으면 10점 줄). 어느 쪽이 나은지는 직접 보고 고르세요.

[7H 편집기(F3) 한글 표시 (0.12.17)]
 7H 에서 F3 편집기가 F2 보기처럼 7H 격자(줄 높이 10점, 7H 21줄이면 본문 19줄, LINES = tight 면 23줄/본문 21줄)로 한글을 보여 줍니다. 글은 UTF-8 로 읽습니다 (한글 음절 = 두 칸, BOM 은 폭 0, 그 밖의 다바이트 글자는 ? 한 칸). 한 줄 80칸에서 줄을 접을 때 한글 한 글자를 쪼개지 않고, 위/아래·쪽 이동·스크롤·커서 칸 계산이 칸 폭을 따릅니다.
 0.12.17 은 보기만이었고, 0.12.18 부터 7H 편집기의 ←→·BS·DEL 이 UTF-8 글자 단위입니다 (한글 한 글자 = 3바이트를 한 번에 건너뛰고 지움, 줄 끝·HOME/SELECT 는 글자 경계). SCREEN 0·7 편집기는 바이트 단위 그대로입니다.

[7H 편집기 글자 단위 (0.12.18)]
 7H 편집기에서 ←→ 는 UTF-8 글자 하나씩, BS·DEL 은 글자 하나(한글이면 3바이트)를 지웁니다. 위/아래는 칸 폭(한글 2칸) 기준으로 같은 칸 근처에 맞추고, 접힌 줄의 끝(SELECT)은 마지막 글자의 처음입니다. Ctrl+S 저장은 바이트를 그대로 써서 BOM·다른 줄이 보존됩니다.

[7H 편집기 한글 입력·UTF-8 저장 (0.12.19)]
 7H 편집기(F3)에서 MSX 한/영(KANA/CODE) 키로 한글 <-> 영문을 바꿉니다 (제목 줄 오른쪽에 [HAN] 표시, 편집기를 닫으면 KANA 잠금·램프가 꺼짐). 한글 모드에서 영문 자판을 두벌식으로 읽어(이름 입력과 같은 조합기: 겹모음·겹받침·받침 넘김, 조합 중 BS 는 종성->중성->초성 순) 한글을 커서 자리에 UTF-8(한 글자 3바이트)로 넣고, 조합 중인 글자는 계속 바뀝니다. 그 밖의 키(이동·영문 등)는 조합을 끝냅니다.
 저장(Ctrl+S)은 본문 바이트를 그대로 쓰므로 UTF-8 로 저장되고 BOM·다른 줄이 보존됩니다. 7H 에서 본문이 UTF-8 이 아니면(EUC-KR 등) 열 때 "Not valid UTF-8 (EUC-KR?)" 확인 팝업이 뜨며, Y 로 열면 그 부분은 ? 로 보이고 바이트는 그대로 저장됩니다 (EUC-KR 변환은 하지 않음: F2 보기로 읽으세요). 파일 최대 14848바이트 그대로(한글 3바이트라 글자 수는 줄어듦), 찾기/바꾸기는 없습니다.

[아이콘 새 안 (0.12.20)]
 SCREEN 7·7H 목록의 파일 아이콘(폴더·프로그램·글·그림·음악·압축·롬·일반 파일·위 폴더)을 마스터님이 확정한 새 모양으로 바꿨습니다 (화살표 <- -> 는 그대로).

[얇은 선 띠 · 목록 줄 늘림 (0.12.21)]
 SCREEN 7·7H 의 구분선 줄 3개(패널 머리 아래, 목록 아래, 기능키 위)를 한 글자 줄 전체가 아니라 4점 띠(가운데 2점 선)로 그리고 패널 사이 세로선도 이어 그립니다. 남는 점으로 목록 줄이 늘었습니다: SCREEN 7 20 -> 22줄, 7H 15 -> 17줄 (LINES = tight 는 17 -> 19줄). 글자 화면(0)은 그대로입니다.
 팝업·도움말·보기·편집기·찾기·트리는 기존 균일 줄 격자를 그대로 쓰고, 닫히면 전체를 다시 그립니다 (화면이 어긋나지 않게 목록 화면에서만 얇은 선 배치).

[정보 줄 화살표 정렬 (0.12.22)]
 활성 패널 화살표의 오른쪽 끝이 구분선·목록의 오른쪽 끝과, 왼쪽 화살표의 왼쪽 끝이 선·목록의 왼쪽 시작과 같은 x 가 되게 맞췄습니다 (SCREEN 7·7H 오른쪽 아이콘은 칸 78 에서 2점 왼쪽, 글자 화면 -> 는 칸 77~78).

[F5 BASIC 복귀 수정 (0.12.23)]
 F5 로 BASIC 에 갔다가 CALL SYSTEM (또는 _SYSTEM) 을 치면 X86FC 로 돌아옵니다. 실기(turboR/Nextor)에서 DOS 가 다시 뜬 뒤 글쇠 버퍼(또는 AUTOEXEC.BAT)가 입력을 지워 X86FC 가 안 뜨던 것을 고쳐, 훅이 직접 입력한 줄 끝의 맨 CALL SYSTEM 을 CALL SYSTEM("X86FC 전체 경로") 로 바꿔 BASIC 이 DOS2/Nextor 표준 기능으로 X86FC 를 실행하게 했습니다 (글쇠 버퍼에 기대지 않음). X86FC 를 F10 으로 끝내면 DOS 프롬프트로 갑니다. 줄 뒤에 다른 글이 있거나 프로그램 안의 SYSTEM 이면 예전 방식(글쇠 버퍼 주입)입니다.

[소스 주석 복구 (0.12.24)]
 소스(x86fc.asm 등)의 깨져 보이던 주석을 한글로 되살리고 버전 이력을 판마다 한 줄로 정리했습니다. 프로그램(COM·OVL)은 0.12.23 과 바이트까지 같습니다.

[1점 가는 선 (0.12.25)]
 구분선(패널 머리 아래·목록 아래·기능키 위 가로선과 패널 사이 세로선)을 1점 두께로 바꾸고 가로선과 세로선이 만나는 곳·모서리를 틈 없이 이었습니다 (SCREEN 7·7H 는 띠 안 1점 선, 글자 화면은 선 글자 모양 01h~09h 를 1점 선으로 다시 그림, 팝업 테두리도 같은 모양). 줄 높이·목록 줄 수는 그대로입니다.

[활성 화살표 잔상 수정 (0.12.26)]
 SCREEN 7·7H 에서 Tab 으로 활성 패널을 바꾸면 이전 쪽 정보 줄 화살표가 지워지지 않고 양쪽에 남던 것을 고쳤습니다 (정보 줄 해시가 같다고 건너뛰던 것). 활성 패널이 바뀌면 정보 줄 전체를 다시 그립니다. 글자 화면(0)은 원래 문제가 없었습니다.

[내부 명령 #VIEW · #EDIT (0.12.27)]
 X86FC.INI 연결 줄에 `HLP = #VIEW` 처럼 쓰면 Enter 로 그 확장자 파일을 내부 텍스트 보기(F2 와 같음)로, `#EDIT` 는 내부 편집기(F3 와 같음, 글 형식이 아니어도 묻지 않고 바로 엽니다)로 엽니다. `HLP = #VIEW;AKID %s` 처럼 다른 명령과 `;` 로 이으면 예전처럼 풀다운 목록에서 고르고, 목록에는 View (internal) / Edit (internal) 로 보입니다. Ctrl+F3 관리 창에서도 보이며 INS 로 `#VIEW` 를 직접 입력해 추가할 수 있습니다. 모르는 `#` 명령은 'Unknown internal command' 팝업이 뜹니다.

[좌우 테두리선 (0.12.28)]
 SCREEN 7·7H 화면 좌우 바깥 여백(x 14, x 491)에 1점 세로선을 넣어 패널 전체를 틀로 감쌌습니다. 가로선 3개가 테두리까지 이어지고 교차부·모서리에 틈이 없습니다. 팝업·도움말·보기·편집기 등은 테두리 없이 전체 격자를 쓰고, 목록 화면으로 돌아오면 다시 그립니다. 글자 화면(0)은 그대로입니다.

[맨 위 테두리선 (0.12.29)]
 SCREEN 7·7H 화면 맨 위에도 1점 가로 테두리선을 넣어 틀을 닫았습니다 (모서리 ┌ ┐ 와 가운데 세로선과 만나는 ┬ 가 틈 없이 이어짐). 자리는 선 띠를 4점에서 3점으로 줄여서 만들었고, 목록 줄 수(SCREEN 7 22, 7H 17, tight 19)는 그대로입니다. 글자 화면(0)은 그대로입니다.

[F4 로 0 -> SCREEN 7 틀 수정 (0.12.30)]
 글자 화면에서 F4 로 SCREEN 7 로 바꾸면 얇은 선 배치(틀·맨 위 선·목록 22줄)가 적용되지 않고 예전 격자로 뜨던 것을 고쳤습니다 (시작할 때 INI·/7 로 SCREEN 7 을 고르거나 7H 를 거치면 정상이었음).

[선과 글자 간격 1점 · 목록 줄 늘림 (0.12.31)]
 SCREEN 7·7H 의 선 띠를 글꼴 셀의 빈 점까지 계산해 줄여서, 모든 선과 글자 사이가 보이는 간격 1점이 되게 했습니다. 남는 점으로 7H 목록이 17 -> 20줄, 7H tight 가 19 -> 20줄로 늘었습니다 (SCREEN 7 은 22줄 그대로, 남는 3점은 맨 아래). 7H 는 목록·경로 줄을 9점 줄로 그리고 한글이 나오는 정보 줄만 10점 줄이며, 팝업·보기·편집기는 예전처럼 10점 격자입니다.

[DOS 화면 깨짐 수정 (0.12.32)]
 SCREEN 7·7H 에서 F9 드라이브 풀다운(·열기 목록·사용자 메뉴·정렬) 뒤 ESC 로 DOS 화면을 보면 이상한 글자가 보이고 화면 아래·위에 잔상이 남던 것을 고쳤습니다 (0.12.21 부터). 팝업 목록 안에서 화면을 다시 그릴 때 균일 격자로 28줄 표를 그려 화면 아래(VRAM 맡김 자리)를 덮어쓰던 것입니다.

[팝업 닫을 때 팝업 자리만 다시 그림 (0.12.33)]
 SCREEN 7·7H 에서 팝업·풀다운(삭제·덮어쓰기·입력창·F5 확인·드라이브·정렬·Quick-Dir·열기 목록·사용자 메뉴 등)을 닫을 때 화면 전체 해시를 비워 전체가 깜박이던 것을, 팝업이 덮었던 줄만 다시 그리도록 고쳤습니다 (팝업 위 팝업도 마찬가지). 전체 화면을 쓰는 보기·편집기·찾기·트리·도움말은 예전처럼 전체를 다시 그립니다. 글자 화면(0)은 그대로입니다.

[Shift 를 누르는 동안 F6~F10 유지 (0.12.35)]
 실기에서 Shift 를 누르고 있으면 기능키 줄이 F6~F10 으로 바뀌었다가 3초쯤 뒤 F1~F5 로 돌아가던 것에 대비해, Shift 판정을 SNSMAT 과 BIOS 키 인터럽트의 NEWKEY 표 두 곳에서 읽고 하나라도 눌림이면 눌림으로 보며, 뗌은 1/20초 이상 계속 뗀 것으로 읽혔을 때만 인정합니다 (에뮬레이터에서는 처음부터 25초 이상 유지됨). 메모리 확보로 폴더당 항목 한도가 192 -> 190개가 됐습니다.

[기능키 줄이 그리는 순간의 Shift 를 읽음 (0.12.36)]
 기능키 줄(F1~F5 / Shift 를 누르면 F6~F10)을 어디서 그리든 그리는 순간의 Shift 상태(SNSMAT + NEWKEY)를 직접 읽어 그립니다. 키 기다리는 루프에서 Shift 상태를 비교할 때 BIOS 호출이 망가뜨리는 레지스터에 기대지 않게 고쳤습니다.

[압축 파일 목록 보기 (0.12.37)]
 연결된 프로그램이 없는 파일에서 Enter 를 누르면 파일 앞부분의 서명으로 압축 파일인지 알아보고, LZH·LHA·PMA(머리 수준 0·1·2), ZIP, ARJ 이면 전체 화면 목록(이름·원래 크기·압축 크기·날짜·방식)을 보여 줍니다. ↑↓ 한 줄, ←→ 한 쪽, HOME 처음, B 끝, ESC 닫기(같은 줄로 복귀). 이번 판은 목록 보기만이고 풀기는 다음 판입니다. 압축 안 이름이 한글이면 아직 ? 로 보일 수 있습니다. 항목 250개까지 보입니다.

[LZH 풀기 (0.12.38)]
 압축 목록에서 Space = 표시(여러 개), A = 모두 표시·해제, Enter 또는 INS = 표시한 파일(없으면 커서 파일)을 반대편 패널의 폴더로 풉니다. LZH/LHA 의 -lh0-(저장)·-lh4-·-lh5- 방식을 풀고 머리 수준 0·1·2 를 읽으며, 풀 때 CRC16 을 검사하고(틀리면 'CRC error. Delete?' 질문) 날짜·시간을 보존합니다. 압축 안의 폴더 경로는 폴더를 만들며 풀고, 이름은 8.3 으로 안전하게 바꿉니다(긴 이름·한글 이름 보존은 아직 없음). 같은 이름이 있으면 덮어쓰기 질문(Y/N/A/Esc), 진행 팝업에서 ESC 로 중단하면 풀던 파일은 지웁니다. 풀기는 매퍼 쪽 하나(윈도 8KB·표)를 쓰므로 여유 매퍼 쪽이 없으면 'No free mapper page' 안내만 나옵니다. -lh1-·-lh6-·-lh7- 은 풀지 못합니다('Unsupported method'). ARJ·PMA 풀기는 다음 판입니다(ZIP 은 아래). 속도는 비트 단위 해석이라 느립니다(에뮬레이터 Z80 에서 150KB 약 40초).

[편집기 큰 클립보드 (0.12.50)]
 편집기 복사·자르기·붙이기의 클립보드가 760바이트에서 편집 글 크기(14848바이트)까지 늘었습니다. 클립보드는 별도 매퍼 쪽에 두므로 여유 쪽이 하나 더 있어야 하고, 쪽이 없으면 예전처럼 760바이트('Block too big')입니다. 편집기를 닫으면 사라집니다.

[글자 화면(SCREEN 0) 다듬기 (0.12.49)]
 글자 화면에서 패널 오른쪽 끝(열 79)에 테두리 선이 생겼습니다(왼쪽 끝은 패널 글이 쓰는 자리라 없음). 확인 팝업(예/아니오, 입력 창)을 닫을 때 팝업이 덮은 칸만 되돌리므로 취소하면 화면을 다시 그리지 않아 깜박임·지연이 없습니다.

[압축 풀기 속도 (0.12.48)]
 LZH·ZIP·ARJ 풀기를 빠르게 했습니다(허프만 조회표·일치 복사·CRC 개선). 에뮬레이터 Z80 에서 120KB 텍스트 기준 LZH 2400 → 1600, ZIP 3200 → 1600 프레임 정도로 줄었습니다(남은 시간은 대부분 디스크 쓰기).

[내부 정리 (0.12.47)]
 오버레이를 더 잘게 나눠(압축 풀기·편집기 큰 파일 명령 분리) 오버레이 창을 줄이고, 패널 하나가 담는 항목 수를 180 에서 191 개로 늘렸습니다. 사용 방법은 그대로입니다.

[편집기 EUC-KR (0.12.46)]
 7H 에서 F3 로 연 글이 UTF-8 이 아니고 EUC-KR(KS X 1001 한글 완성형)로 보이면 'Convert EUC-KR to UTF-8? (Symbols/Hanja will be lost)' 하고 묻습니다. Y 면 UTF-8 로 바꿔 열고(한글 완성형만 바뀌며 기호·한자는 ?), 저장하면 기본으로 EUC-KR 로 되돌려 저장합니다. 되돌릴 수 없는 글자(KS X 1001 에 없는 음절·한글 밖의 글자)가 있거나 글이 13960바이트를 넘으면 알리고 'Save as UTF-8?' 로 묻습니다(예 = UTF-8 로 저장하고 이후 UTF-8 글). N 이면 예전처럼 바이트 그대로(? 로 보임) 여부를 묻습니다. 바꿀 수 있는 크기는 약 9300바이트까지이고 큰 파일(창 방식)은 이 확인을 하지 않습니다. 변환 표는 X86FC.OVL 안 글꼴 뒤 표를 씁니다. EUC-KR 로 저장할 때는 되돌리기 기록이 비워집니다.

[편집기 큰 파일 (0.12.45)]
 F3 편집기가 14848바이트보다 큰 파일도 엽니다(디스크 크기 제한만 있음). 파일의 한 토막(창, 약 12KB)만 글 버퍼에 읽고, 커서가 창 끝(또는 앞)에 다가오면 창을 옮겨 이어서 읽습니다. 창을 옮기기 전에 고친 곳이 있으면 파일에 되씁니다(앞부분·창·뒷부분을 폴더의 임시 파일 X86FC.TMP 에 모았다가 원본에 되복사: 저장이 느릴 수 있음, 디스크에 파일 크기만큼 여유 필요). 창을 옮기면 되돌리기 기록과 선택은 비워집니다. 줄:칸 표시는 파일 전체 기준 줄 번호입니다. Ctrl+F 찾기는 뒤쪽 창들을 차례로 읽으며 찾고(처음으로 되돌아가지는 않음), Ctrl+G 는 먼 줄로 창을 옮기며, Ctrl+R 의 '전부 바꾸기'는 파일 전체를 한 번에 처리합니다. 저장(Ctrl+S, 닫을 때 Y)은 파일 전체를 다시 씁니다. 큰 파일에서는 EUC-KR 확인(7H)을 하지 않습니다.

[편집기 되돌리기 (0.12.44)]
 F3 편집기에서 Ctrl+Z = 되돌리기. 입력·지우기·붙이기·자르기·줄 지우기·줄 복제·한 건씩 바꾸기가 기록되며 Ctrl+Z 를 누를 때마다 한 건(글자 입력은 한 바이트, 한글은 세 바이트 단위)씩 거꾸로 되돌립니다. 기록은 글 버퍼 쪽의 뒤쪽 1536바이트에 쌓이고 가득 차면 가장 오래된 것부터가 아니라 한꺼번에 비우고 새로 시작합니다. '전부 바꾸기(A)'는 되돌릴 수 없고 그때까지의 기록을 비웁니다. 되돌리기 기록 자리를 위해 편집할 수 있는 파일 크기가 16000 → 14848바이트로 줄었습니다(다음 판에서 큰 파일 지원 예정).

[편집기 블록 선택·복사·붙이기 (0.12.43)]
 F3 편집기에서: Shift+방향키(←→↑↓, HOME, SELECT)로 선택을 시작·넓히고(선택한 글은 반전으로 보임), 또는 Ctrl+B 로 시작 표시를 한 뒤 보통 이동키로 넓힙니다(Ctrl+B 를 다시 누르면 해제). Ctrl+C 복사, Ctrl+X 자르기(SELECT 키가 아니라 Ctrl 을 누른 X), Ctrl+V 붙이기(선택이 있으면 그 자리를 바꿈), 선택이 있을 때 BS·DEL 은 선택을 지웁니다. Ctrl+Y 는 줄 지우기, Ctrl+D 는 줄 복제(커서는 복제한 줄로). 클립보드는 0.12.50 부터 별도 쪽을 얻으면 글 크기까지, 못 얻으면 760바이트('Block too big')이고 편집기를 닫으면 사라집니다. 7H 한글 글에서도 글자 단위로 동작합니다. 편집기 시작(파일 열기)을 별도 오버레이로 옮겼습니다.

[편집기 찾기·바꾸기·줄 이동 (0.12.42)]
 F3 편집기에서: Ctrl+F = 찾기(입력 창), F3 또는 Ctrl+N = 다음 찾기(글 끝에서 처음으로 한 번 감김), Ctrl+R = 바꾸기(찾을 글 → 바꿀 글 입력 뒤 하나씩 묻는 창: Y 바꿈 / N 건너뜀 / A 전부 / Esc 그만), Ctrl+G = 줄 번호로 이동. 제목 줄 오른쪽에 커서의 줄:칸이 보입니다(7H 에서 칸은 글자 수). 영문 대소문자를 가리지 않고, 7H 에서는 한글 검색어도 UTF-8 로 바꿔 찾습니다. 앞서 넣은 글은 입력 창에 미리 채워지고 첫 글자를 치면 지워집니다. 바꿀 글이 길어져 버퍼(14848바이트)가 모자라면 'No room in the buffer' 안내 후 멈춥니다. 명령은 별도 오버레이(10번 칸)에서 하므로 처음 쓸 때 X86FC.OVL 을 한 번 더 읽습니다.

[ARJ·PMA 풀기 (0.12.41)]
 ARJ 목록에서도 같은 키로 풉니다: 방식 0(저장)·1·2·3(허프만 LZ77, 창 26KB) 을 풀고 CRC32 검사·날짜 보존을 하며, 방식 4(빠른 방식)·암호 건 파일은 'Unsupported method' 입니다. 창이 ZIP 과 같은 방식으로 여분 매퍼 쪽을 써서 여분 쪽 2개면 26KB 전부, 1개면 16~24KB 까지(그보다 먼 참조는 'Need more mapper pages 6'). 유닉스에서 만든 ARJ 의 날짜(유닉스 시각)도 올바로 보입니다. PMA 는 -pm0-(저장)만 풉니다. -pm1-·-pm2- 는 'Unsupported method' 입니다(시험용 압축 도구를 구할 수 없어 알고리즘을 확인하지 못함).

[ZIP 풀기 (0.12.39, 창 확장 0.12.40)]
 ZIP 목록에서도 같은 키(Space/A/Enter/INS)로 풉니다. stored(저장)와 deflate(고정·동적 허프만) 방식을 풀고, CRC32 를 검사하며(틀리면 'CRC error. Delete?'), 4바이트 크기와 하위 폴더 경로를 지원합니다. 풀기 중 ESC 로 중단하면 풀던 파일은 지웁니다. deflate 의 되짚기 창은 매퍼 쪽을 더 써서 넓힙니다: 풀 때 여분 매퍼 쪽을 최대 2개 더 확보하고(끝나면 돌려줌) 여분 쪽 2개면 32KB 이상(보통 ZIP 의 32KB 창), 1개면 16~24KB, 0개면 8KB 까지의 거리만 풀 수 있습니다. 그보다 먼 곳을 참조하는 자료는 'Need more mapper pages 6' 안내 후 그 파일을 지웁니다(CPC-400 처럼 여분 쪽이 적은 기종에서 32KB 창으로 만든 큰 ZIP 이 해당). 암호 걸린 ZIP·deflate64·bzip2 는 'Unsupported method' 입니다. ARJ 는 아래, PMA 는 아래 설명.
 이번 판에서 메모리 확보를 위해 폴더당 항목 한도가 190 -> 180개가 됐습니다.

[알려진 한계] 한 폴더 항목 최대 180개 (0.12.8: 명령줄 기록 코드 때문에 200 에서 줄임. 0.12.0: 7H 코드 때문에 240 에서 줄임). 한글 입력은 7H 에서만 됩니다 (이름 바꾸기·폴더 만들기, 아래 [한글 입력]).
 Nextor·실기·하드 디스크는 아직 시험하지 못했습니다 (CPC-400 에뮬레이터에서 시험).

[M.INI 변환본] X86FC_from_M.INI = M 의 <EXT> 연결을 X86FC 형식으로 옮긴 것(HV·AKID·APED·BLS·MUPLAY·DBMP 등, 58줄, ';' 로 한 줄에 여러 명령). 쓰려면 X86FC.INI 로 이름을 바꿔 X86FC.COM 옆에 두세요.
M 내부 명령(#GV 등)과 디스크에 없는 프로그램(NV·TV·UNARC 등)은 뺐습니다. (0.12.14 부터 INI 크기 한도 없음)

[파일] ★ X86FC.COM · X86FC.OVL · X86FC.INI 세 개만 같은 폴더에 두면 됩니다 (0.12.14 부터). X86FC.OVL = 보기·편집기·찾기·트리·사용자 메뉴·열기 목록(Ctrl+F3)·도움말(F1)·이동(SELECT) 덩어리 6칸 + 7H 한글 글꼴(11172자 + EUC-KR 표)이 한 파일(약 223KB)로 들어 있습니다. OVL 이 없으면 그 기능만 "X86FC.OVL not found" 안내, 글꼴이 없는 옛 OVL 이면 7H 를 건너뜁니다. MAPINFO.COM (매퍼 쪽수 확인용) · X86FC_src.zip (소스, mkovl.py 가 hgl.bin 을 OVL 뒤에 붙임)

[설정 저장] F4 로 고른 화면 방식과 F8 로 고른 정렬은 X86FC.INI 의 SCREEN = / SORT = 줄로 저장됩니다 (그 줄만 바뀌고 다른 줄·주석·순서는 그대로, INI 가 커도 상관없음). 옛 X86FC.SET 이 있으면 처음 실행 때 INI 로 옮기고 지웁니다.

[사용자 메뉴·Quick-Dir·명령줄 기록] Ctrl+G 메뉴는 INI 의 MENU 제목 = 명령 줄, Ctrl+B Quick-Dir 는 QDIR = 경로 줄, 명령줄(/) 기록은 HIST = 명령 줄(4개)로 저장됩니다. 옛 X86FC.MNU · X86FC.QD · X86FC.HIS 는 처음 실행 때 INI 로 옮기고 지웁니다. 옛 X86FC.HGL 은 이제 쓰지 않으니 지워도 됩니다 (프로그램이 지우지는 않음).
[INI] X86FC_from_M.INI 의 연결(확장자 = 명령)은 X86FC.INI 에 모두 들어 있습니다.

[F2 한글 보기 (0.12.4 새 기능)]
 7H 에서 F2 (텍스트 보기) 를 열면 한글 글을 9x9 점글꼴로 보여 줍니다 (줄 높이 10점, 제목 + 본문 19줄 + 안내 = 21줄, 한글 한 글자 = 두 칸, 한 줄 80칸).
 - 글 인코딩은 파일 앞부분으로 자동 판별: UTF-8 (BOM 있어도 없어도 됨, 한글 음절 외의 글자는 ? 한 칸) · EUC-KR/CP949 (KS X 1001 한글 완성형 2350자, 그 밖 기호·한자는 ? 한 칸) · 그 밖에는 ASCII (80h 이상은 . ). 제목 줄 오른쪽에 UTF-8 / EUC-KR 이 나옵니다.
 - 키는 그대로: 위/아래 한 줄, 왼쪽/오른쪽/SPACE 한 쪽, HOME 처음, B 끝, ESC·F10·Q 닫기. 긴 줄은 80칸에서 접고 (한글은 두 칸으로 세어 한 글자를 쪼개지 않음), 탭·CR·LF 처리는 그대로.
 - EUC-KR 보기는 OVL 안 글꼴 뒤쪽의 표가 있어야 하고, 없으면 ASCII 로 봅니다. SCREEN 0 · 7 (한글 아님) 의 F2 는 예전과 같이 8점 줄 22줄입니다.
 - 7H 는 한글 글자를 글꼴 캐시(256칸)에 두고 모자라면 HGL 파일에서 읽으므로, 한글이 다양한 쪽은 그리는 데 시간이 걸립니다 (실기 속도는 기종·저장장치에 따라 다름).

[0.12.53 Ctrl+C 로 끊어도 X86FC 로 돌아옴] (실기 확인됨)
 프로그램(X86MP3 등)을 돌리다 Ctrl+C 로 끊으면 MSX-DOS2 가 "Terminate batch file (Y/N)?" 를 묻고, Y 를 누르면 X86FC 로 돌아오지 못하고 A> 에 남던 문제를 고쳤습니다. 이제 배치 파일이 프로그램을 하위 COMMAND2 (%SHELL%) 로 돌리므로, Ctrl+C 로 끊겨도 그 질문 없이 바로 X86FC 로 돌아옵니다.
 - 하위 COMMAND2 가 TPA 를 약 1.5KB(0600h) 차지하므로 프로그램이 쓸 수 있는 메모리가 그만큼 줄어듭니다. 메모리가 아주 빠듯한 프로그램이 안 돌면 알려 주세요.
 - 패널 하나의 항목 수 한도를 191 에서 190 개로 줄였습니다 (코드가 조금 늘어 복사 버퍼 최소 2KB 를 지키려고).

[0.12.56 압축을 푼 뒤 패널 목록이 바로 새로 고쳐짐]
 압축 파일이 있는 폴더에 풀면 풀린 파일이 압축 화면을 나가도 패널 목록에 안 보이다가 폴더를 나갔다 들어와야 보이던 것을 고쳤습니다. 다 풀면 양쪽 패널을 다시 읽고, 커서는 압축 파일에 그대로 둡니다.

[0.12.55 압축 풀 폴더를 풀다운으로 고르고, 폴더를 만들 수 있음]
 압축 파일(ZIP·LZH·ARJ·PMA) 목록에서 A(모두 표시) 또는 Space 로 고른 뒤 Enter(또는 INS)를 누르면 "Extract to: 폴더" 풀다운이 뜹니다 (예전에는 보이지 않는 반대 패널 폴더로 바로 풀었음).
 - 처음 폴더 = 반대 패널의 폴더. Up/Down 이동, Enter = 폴더로 들어감, ".." 또는 BS = 위 폴더, \ = 루트, 글자 = 그 글자로 시작하는 폴더, Left/Right 한 쪽.
 - 맨 위 "<Extract here>" 에서 Enter = 지금 보이는 폴더에 풀기. ESC = 취소(압축 목록으로 돌아감).
 - F7 (또는 Ctrl+F) = 보이는 폴더 안에 새 폴더 만들기: 이름을 입력하면 8.3 (영문 대문자·숫자·_ - , 8글자까지; 빈칸·점은 빼고 그 밖의 글자는 _)로 만들고 그 폴더에 커서가 갑니다.
 - 다 풀면 "Extracted N file(s) to 폴더" 안내가 뜨고, 반대 패널이 고른 폴더를 보여 줍니다 (한 파일도 못 풀었으면 N = 0 으로 알 수 있음).
 - 폴더 칸은 한 번에 70개까지 보입니다 (그 넘는 폴더는 이름 첫 글자 점프로 못 찾음).
 - X86FC.OVL 이 커졌습니다 (약 255KB: 오버레이 칸 하나 추가).

[0.12.54 F4 화면 바꿈(글자 -> SCREEN 7)이 빨라짐] (실기 확인됨)
 F4 로 글자 화면에서 SCREEN 7 로 바꿀 때 걸리던 시간을 줄였습니다 (에뮬레이터 측정: 누른 뒤 화면이 다 나오기까지 약 4.8초 -> 약 2.7초).
 - 글자 <-> SCREEN 7 은 한글 여부가 같아서 두 패널의 긴 이름을 디스크에서 다시 읽지 않습니다 (SCREEN 7 <-> 7H 일 때만 다시 읽음).
 - 화면을 먼저 그린 뒤에 X86FC.INI 에 화면 방식을 저장합니다 (저장하는 동안 빈 화면이 보이지 않음).
 - 남은 시간은 SCREEN 7 글꼴판 12장을 만드는 시간(약 1~1.5초)과 BIOS 화면 전환입니다.
